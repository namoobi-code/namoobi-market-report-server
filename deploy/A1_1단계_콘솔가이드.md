# 1단계 상세 — OCI 콘솔에서 A1 인스턴스 만들기

현 서버(161.33.190.254)에서 실측한 값으로 채운 가이드. **이 단계만 사용자가 직접**, 이후는 SSH로 내가 진행.

---

## 0단계 — 만들기 전에 "쓸 수 있는지" 먼저 확인 (1분)

인스턴스를 만들기 전에 두 가지를 봐야 합니다. **둘은 다른 문제**입니다.

| 확인할 것 | 뜻 | 어디서 |
|---|---|---|
| **① 한도(Limit)** | 내 계정에 A1 코어가 몇 개 배정돼 있나 = *무료로 쓸 권리* | 콘솔 Limits 페이지 |
| **② 용량(Capacity)** | 지금 도쿄 데이터센터에 빈 자리가 있나 = *실제로 만들어지나* | 생성 시도해야 확실 |

한도가 4여도 용량이 없으면 생성이 실패하고, 반대로 용량이 있어도 한도가 0이면 못 만듭니다.

### ① 한도 확인 — 무료 4코어가 배정돼 있나

1. https://cloud.oracle.com 로그인 (우측 상단 리전 **Japan East (Tokyo)** 확인)
2. 좌측 메뉴(☰) → **Governance & Administration** → **Limits, Quotas and Usage**
3. 필터를 이렇게 맞춥니다
   - **Service**: `Compute`
   - **Scope**: `IKhn:AP-TOKYO-1-AD-1` (도쿄는 AD 1개)
   - 검색창에 `Ampere` 입력
4. **"Cores for Ampere A1 based VM and BM instances"** 행을 봅니다

| 표시 | 해석 |
|---|---|
| Limit **4** · Used **0** · Available **4** | ✅ 무료 4코어 그대로 남아 있음 → 진행 |
| Limit 4 · Used 1~3 | 다른 A1 인스턴스가 이미 있음 → 남은 만큼만 가능 |
| Limit **0** | ❌ 계정에 A1 배정이 없음 → 아래 "한도가 0일 때" 참고 |

메모리도 같은 화면에서 `Memory for Ampere A1...` 로 확인 — **24GB** 면 정상입니다.

### ② 계정이 Always Free 인지 확인

- 좌측 메뉴 → **Billing & Cost Management** → **Subscriptions / Upgrade and Payment**
- 화면에 **"Upgrade to Paid"** 버튼이 보이면 → 지금은 **Always Free(무료 체험 이후)** 계정입니다.
- A1 4 OCPU / 24GB 는 **Always Free 대상**이라 이 상태에서도 요금이 붙지 않습니다.
  생성 화면에서 shape 옆에 초록색 **"Always Free eligible"** 배지가 뜨는지 한 번 더 확인하면 확실합니다.

### ③ 용량 확인 — 결국 "만들어 보는 것"이 유일한 방법

오라클은 남은 호스트 용량을 미리 알려주지 않습니다. 아래 2번 절차대로 생성을 눌러보면
**성공하거나, `Out of host capacity` 에러가 즉시 뜹니다.** 실패해도 **요금·불이익 없고 몇 번이든 재시도** 가능합니다.
즉 0단계 ①②만 확인되면 바로 생성을 시도하는 게 가장 빠릅니다.

### 한도가 0일 때

무료 체험 기간이 끝난 계정에서 종종 A1 한도가 0으로 잡힙니다. 해결책:
1. **Upgrade to Paid** 로 계정 전환 — Always Free 리소스는 계속 0원, A1 한도·우선순위가 살아납니다(가장 확실).
2. 또는 **Limits 페이지 → Request a service limit increase** 로 증설 요청(무료 계정은 거절되는 경우가 많음).

## 1. 접속

| | |
|---|---|
| 주소 | **https://cloud.oracle.com** |
| 로그인 | 오라클 클라우드 계정 이메일 + 비밀번호 (가입 시 만든 것) |
| 테넌시 | 로그인 화면에서 물으면 계정 생성 시 정한 **테넌시 이름** 입력 |

> 다른 리전에서 만들면 기존 VCN·보안규칙을 못 씁니다.

## 2. 생성 화면 열기

좌측 햄버거 메뉴(☰) → **Compute** → **Instances** → 파란 버튼 **Create instance**

---

## 3. 입력값 (현 서버 실측 기준)

### ① Name
`namoobi-a1` (자유롭게)

### ② Placement — Availability domain
- 현 서버: **IKhn:AP-TOKYO-1-AD-1**
- 도쿄는 AD가 1개뿐이라 선택지가 하나입니다. 그대로 두세요.

### ③ Image and shape  ← **핵심**

**Image**: `Change image` → **Ubuntu** → **Canonical Ubuntu 24.04** 선택
> 중요: 목록에서 **aarch64 / ARM** 표기가 있는 이미지를 골라야 합니다.
> Shape을 A1으로 먼저 바꾸면 ARM 이미지만 나오니, **Shape → Image 순서**가 편합니다.

**Shape**: `Change shape` →
1. 탭에서 **Ampere** 선택
2. **VM.Standard.A1.Flex** 클릭
3. 슬라이더: **OCPU 4**, **Memory 24 GB**
4. "Always Free eligible" 초록 배지가 보이는지 확인

### ④ Primary VNIC — 네트워크 (기존과 동일하게)
- **Virtual cloud network**: 기존 VCN 선택 (서브넷 CIDR **10.0.0.0/24** 인 것 — 현 서버가 10.0.0.186)
- **Subnet**: 위 VCN의 **public subnet**
- **Public IPv4 address**: **Assign a public IPv4 address** 체크 ✅ (안 하면 외부 접속 불가)

### ⑤ Add SSH keys ← **반드시 아래 키를 붙여넣기**
`Paste public keys` 선택 후 이 한 줄을 그대로 붙여넣습니다:

```
ssh-ed25519 AAAAC3NzaC1lZDI1NTE5AAAAILzaw7Fo3z0gOsQg0BbTe5xzX+UfQbhLZYJzN1QpFX1Y namoobi-deploy
```

> 지금 쓰는 배포키와 같은 키라, 생성 직후 제가 바로 접속해서 2단계부터 진행할 수 있습니다.
> (이 값은 공개키라 노출돼도 안전합니다. 짝이 되는 비밀키는 SECURITY 폴더에만 있습니다.)

### ⑥ Boot volume
- **Specify a custom boot volume size** 체크 → **100** GB 입력
  (무료 한도는 총 200GB. A1 하나만 쓰면 100~200 아무거나. 현 서버 45GB에 7.5GB만 썼으니 100이면 넉넉)
- VPU는 기본값(10) 그대로

### ⑦ 생성
하단 **Create** 클릭 → 1~2분 뒤 상태가 **RUNNING** 으로 바뀌고 **Public IP address** 가 표시됩니다.
→ **그 IP를 저에게 알려주시면 됩니다.**

## 4. 용량 부족 에러가 뜨면

> `Out of host capacity` / `Out of capacity for shape VM.Standard.A1.Flex`

도쿄 리전에서 흔합니다. 순서대로 시도하세요.

1. **잠시 후 재시도** — 몇 분~몇 시간 단위로 자리가 납니다. 새벽(한국시간 02~06시)에 잘 열립니다.
2. **사양 낮추기** — OCPU 2 / Memory 12GB. 그래도 지금(1 OCPU·1GB)보다 12배입니다.
3. **다른 리전** — 예: Osaka(ap-osaka-1), Seoul(ap-seoul-1, 리전 구독 필요).
   단 리전이 다르면 VCN·보안규칙을 새로 만들어야 해서 손이 더 갑니다(제가 안내 가능).
4. **유료 계정 전환(Upgrade to Paid)** — 무료 등급이라도 유료 계정으로 바꾸면 A1 우선순위가 올라갑니다.
   Always Free 리소스는 계속 무료라 **A1 4/24는 여전히 0원**입니다. 실제로 가장 확실한 방법입니다.

---

## 5. 보안 목록(방화벽) 확인 — 기존 VCN을 쓰면 대부분 이미 됨

기존 VCN을 골랐다면 80/443 규칙이 이미 있습니다. 혹시 나중에 접속이 안 되면
**Networking → Virtual cloud networks → (VCN) → Security Lists → Default Security List** 에서
Ingress Rules에 아래가 있는지 확인하세요.

| Source | Protocol | Port |
|---|---|---|
| 0.0.0.0/0 | TCP | 22 (SSH) |
| 0.0.0.0/0 | TCP | 80 (HTTP) |
| 0.0.0.0/0 | TCP | 443 (HTTPS) |

---

## 6. 생성 후 — 저에게 알려줄 것

1. **Public IP** (예: 140.x.x.x)
2. 위 3번의 용량 에러가 났다면 어떤 메시지였는지

그러면 제가 SSH로 접속해 2~6단계(패키지 설치 → 코드·데이터 이전 → 서비스·크론 → 검증 → HTTPS)를 진행합니다.
**구 서버는 그대로 살려둔 채** 신규에서 검증을 마친 뒤 DuckDNS만 돌리므로, 실패해도 원복이 쉽습니다.
